# Contributing to Lantern Sudoku

Thanks for helping. Bug reports, accessibility feedback and pull requests are all welcome: open an issue at <https://github.com/ukpratik/lantern-sudoku/issues>. For anything larger than a small fix, please open an issue first so we can agree on the approach.

A few rules keep the app private, small and maintainable.

1. **No permissions, no network.** Nothing may add `INTERNET` or any other permission. `scripts/check-permissions.sh` fails the build if a release APK's merged manifest requests any permission (the allowlist is empty; only the app-private `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` that AndroidX adds is tolerated).
2. **Licences.** Dependencies must be FOSS and GPL-3.0-compatible (Apache-2.0, MIT, BSD, OFL). The AboutLibraries licence gate fails the release build otherwise. Proprietary code is allowed only in the `play` flavour (today: the In-App Review prompt); the `fdroid` flavour must stay free of it.
3. **Architecture.**
   - `:engine` is pure Kotlin with no Android dependency: model, solver, techniques, hints and the game reducer live there and are unit-tested on the JVM.
   - `:app` is Jetpack Compose and Material 3; colours come from `design/tokens.css` through `Palettes.kt` (regenerate, don't hand-edit), and `PaletteTest` checks they match.
   - The puzzle bank in `bank/v1/` is generated by `tools/generator` and never edited by hand; released records are frozen and the validator fails on any change to them.
   - Keep new dependencies rare, and explain each one in the pull request.
4. **Tests with the code.** New behaviour needs tests (engine logic as JVM unit tests, app behaviour as Robolectric or Compose tests). Run `scripts/ci.sh` before pushing; it is exactly what CI runs (tests, bank validator, lint with warnings as errors, R8 release builds with the licence gate, permission and size gates).
5. **Accessibility.** Every interactive element needs a TalkBack label, touch targets stay at least 48 dp, and screens must work in all four themes and at 200% system text.
6. **Source headers.** Start each new source file with `// SPDX-License-Identifier: GPL-3.0-or-later`.
7. **Commits.** Conventional commits (`feat:`, `fix:`, `build:`, `docs:` …), small and focused.

By contributing you agree that your contribution is licensed under GPL-3.0-or-later.

## Debug hooks

Debug builds (never release builds) accept a few launch extras that set up a state for testing. `--activity-single-top` lets them reach a running app too:

```bash
A=io.github.ukpratik.lanternsudoku.debug/io.github.ukpratik.lanternsudoku.MainActivity
adb shell am start --activity-single-top -n $A --es dbg_load N-H-0123                # start that New-game puzzle
adb shell am start --activity-single-top -n $A --es dbg_load N-H-0123 --es dbg_board <81 chars>   # ...with entries filled in
adb shell am start --activity-single-top -n $A --ez dbg_near_solved true             # one empty cell left (also in the game's ⋮ menu)
adb shell am start --activity-single-top -n $A --es dbg_date 2026-10-15              # set "today" (`clear` resets it)
adb shell am start --activity-single-top -n $A --es dbg_date 2026-10-15 --ez dbg_daily true   # open that day's daily
```
